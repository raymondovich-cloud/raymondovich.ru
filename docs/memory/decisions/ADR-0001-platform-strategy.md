# ADR-0001 — Стратегия платформ

> **Проект:** Raymondovich.ru  
> **Документ:** Architecture Decision Record  
> **Версия:** 1.0  
> **Статус:** Предложено  
> **Дата:** 2026-11-10

## Контекст

Необходимо развивать один продукт для Web, Telegram Mini App и iOS при отсутствии бюджета на платные подписки и без нарушения действующего Web. Основной клиент и первичный рынок — Web.

## Рассмотренные варианты

1. Одновременно разрабатывать три независимых клиента.
2. Сначала Web, затем PWA, Telegram Mini App и iOS.
3. Сначала нативное iOS-приложение, затем Web и Telegram.

## Предложенный выбор

Вариант 2: Web → PWA → Telegram Mini App → iOS. PWA не требует членства Apple Developer. Telegram Mini App подключается после готовности Web и серверной проверки initData. Для iOS по умолчанию рассматривать оболочку с локальным bundle (например, Capacitor), но только после появления бюджета и достаточной нативной ценности. Swift остаётся альтернативой при подтверждённой потребности.

## Последствия

- Не распылять усилия и не поддерживать три независимые бизнес-реализации.
- Сначала закрыть регрессии Web и выделить платформенные границы.
- App Store/TestFlight требуют Apple Developer Program membership; актуальные региональные условия повторно проверять.
- WebView-only приложение имеет риск отказа по Apple Guideline 4.2.
- Service Worker, push, нативные плагины и build pipeline не входят в текущий этап.

## Открытые вопросы владельцу

- Утвердить последовательность и условие старта каждого этапа.
- Подтвердить local bundle как целевой iOS-вариант по умолчанию, не как немедленное обязательство.
