# ADR-0003 — Модель Telegram-аутентификации

> **Проект:** Raymondovich.ru  
> **Документ:** Architecture Decision Record  
> **Версия:** 1.0  
> **Статус:** Предложено  
> **Дата:** 2026-11-10

## Контекст

Telegram Mini App передаёт initData, но клиентские поля не являются доверенными до проверки подписи сервером. Нужно связать Telegram identity с существующей учётной записью Supabase, не допуская эскалации привилегий.

## Рассмотренные варианты

1. Доверять `initDataUnsafe` и переданному клиентом user ID.
2. Проверять исходный `initData` на сервере и привязывать Telegram только через одноразовый challenge, созданный из авторизованной Web-сессии.
3. Создать отдельную Telegram-only учётную запись/сессию и синхронизировать её с Supabase позже.

## Предложенный выбор

Вариант 2. Edge Function проверяет Telegram signature по bot token из server-side secrets, проверяет свежесть `auth_date`, а затем атомарно использует одноразовый challenge, связанный с текущим Supabase user из доверенной авторизованной Web-сессии. Клиент не выбирает user ID и не может повторно использовать challenge.

Для выдачи сессии сначала использовать безопасный fallback: связать identity, затем вход существующим Supabase способом. Автоматический обмен challenge на Supabase session допускается только после отдельного staging-прототипа на официально поддерживаемом Auth flow.

## Запреты

- Не принимать `initDataUnsafe` как доказательство личности.
- Не хранить bot token, service_role или signing secret в клиенте/репозитории.
- Не назначать admin роль по Telegram ID, username, display name, группе, каналу или startParam.
- Не выпускать собственные Supabase JWT и не использовать service_role как пользовательскую сессию.
- Не создавать/изменять production DDL в рамках проектирования.

## Последствия

- Потребуется серверный endpoint и безопасное хранилище одноразовых challenge; конкретная модель данных и DDL будут отдельным согласованием.
- Нужны проверки повторного использования, истечения срока, конкурентного потребления, конфликта привязки и отзыва.
- До завершения auth proof Telegram Mini App не получает автоматическую авторизацию.

## Открытые вопросы владельцу

- Утвердить вариант привязки и fallback session flow.
- Утвердить допустимое окно свежести initData и политику повторного использования.
- Утвердить поведение при уже привязанном Telegram ID или попытке смены аккаунта.
