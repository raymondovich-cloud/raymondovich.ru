> **Дата:** 2026-11-10

---

## 1. Назначение

Каталог `docs/memory/` — долговременная репозиторная память решений и рабочего контекста для владельца и ИИ-агентов. Он помогает сохранять причины архитектурных решений, текущее состояние задач и передавать работу без потери важных ограничений.

При передаче задачи другой модели/человеку handoff должен соответствовать `docs/development.rules/agent.md` §15.2: цель и границы, нормативные документы, утверждённые решения, затронутые файлы, ветка и SHA, выполненное, проверки, проблемы, риски и вопросы владельцу.

## 2. Отличие от модуля Memory платформы

- Репозиторная память — Markdown-документы в Git, используемые командой разработки.
- Модуль Memory платформы — будущий runtime-модуль, который предоставляет контекст/знания внутри продукта и подчиняется `core-interaction-architecture.md` §13.
- Репозиторная память не является API приложения, не хранит пользовательские данные и не подменяет будущий модуль Memory.

## 3. Структура

- `decisions/` — ADR: контекст, варианты, предложенный выбор и последствия.
- `handoff/` — актуальная передача состояния работы следующему участнику.
- `README.md` — правила ведения каталога.

## 4. Правила ведения

1. Каждый документ имеет собственную версию, явный статус, дату и историю версий по AGENT.md §14.
2. Статус «Предложено» или «На утверждении» не равен утверждённому решению.
3. После решения владельца обновлять статус ADR и handoff; не переписывать историю так, будто решение было принято раньше.
4. Устаревшие сведения помечать как заменённые и ссылаться на актуальный документ.
5. Handoff обновлять при каждом существенном завершении этапа и передавать точную ветку/SHA.
6. Не записывать предположения как факты; указывать источник и степень подтверждения.
7. Не дублировать большие спецификации: сохранять ссылку на нормативный документ и краткое объяснение решения.
8. Любое изменение архитектуры или безопасности согласовывать по AGENT.md §10.
9. Не создавать пустые каталоги и файлы; каталог появляется вместе с содержимым.

## 5. Запреты

Запрещено хранить:
- пароли, API keys, bot tokens, service_role и любые секреты;
- access/refresh tokens, cookie, session dumps, PIN-коды;
- персональные данные, контактные данные, адреса, идентификаторы пользователей;
- реальные финансовые сведения, выгрузки БД, приватные логи и данные партнёров;
- содержимое приватных переписок без отдельного основания и согласования.

Для handoff использовать только технические идентификаторы Git (ветка, commit SHA) и обезличенные описания.
