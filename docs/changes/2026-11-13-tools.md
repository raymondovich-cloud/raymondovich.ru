# 2026-11-13 — Tool Management Core

## Проектное решение
- Подготовлена техническая спецификация Tool Management Core версии 1.0: `docs/tool-management-core.md`.
- Зафиксирована двухуровневая модель: личный grant пользователя на инструмент и независимое подключение инструмента к конкретному проекту.
- Подключать/отключать инструмент разрешено только владельцу проекта или пользователю с ролью администратора именно этого проекта.
- Личное право не подключает инструмент автоматически ко всем проектам; отключение в одном проекте не влияет на другие.
- Отзыв или истечение личного grant блокирует использование инструмента во всех проектах.
- Нижняя навигация должна учитывать текущий проектный контекст и показывать только инструменты с действующим личным grant и включённым подключением к выбранному проекту.
- Разделены полномочия подключения инструмента и полномочия его запуска участниками проекта.

## Архитектура
- Domain-контракты и предметная логика остаются в `source/domain/tools/`.
- Сценарии управления относятся к Application; Supabase и внешние интеграции — к Infrastructure; UI — к Presentation.
- Интеграционные адаптеры размещаются отдельно для каждого инструмента в Infrastructure, чтобы не нарушать границы Domain.
- В качестве будущих сущностей описаны `private.user_tool_grants` и `private.project_tool_activations`; это проектная модель, миграции не создавались.

## Ограничения и следующие зависимости
- В текущем репозитории отсутствует полноценная модель Projects/RBAC; точные FK и серверный источник project roles нельзя зафиксировать до разработки Projects.
- Требуется отдельно утвердить, какие роли участников проекта могут запускать подключённые инструменты.
- Требуется согласовать аудит и политику данных после отключения инструмента.
- Supabase, Edge Functions, БД и интерфейс не изменялись. Документ не заявляет готовность механизма или успешность runtime-тестов.
