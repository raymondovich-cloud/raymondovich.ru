# Исправление E2E авторизации и Owner route guard

## Причина
В `router.beforeEach` функция `getRole` объявлялась через `const` внутри блока `try`, но использовалась после завершения этого блока. Переменная была недоступна по области видимости. При проверке роли маршрутного пространства `owner` возникал `ReferenceError`; guard не завершал навигацию ожидаемым перенаправлением или открытием Owner Control Center.

## Исправление
- Получение `getRole` и `getSession` выполняется через объект импортированного auth-модуля.
- Удалён E2E-тест, который пытался импортировать исходный модуль по URL `/source/...` из production-сборки. Такой путь не является публичным ресурсом собранного приложения.
- Проверка восстановленной admin-сессии перенесена на наблюдаемое поведение приложения: доступ к защищённому Owner route и переход к Ideas.
- Проверка обычного пользователя на запрет входа в Owner Control Center сохранена.

## Границы проверки
Тесты используют синтетическую Supabase-сессию и mock-ответы для данных Owner Workspace. Они проверяют клиентскую маршрутизацию и извлечение роли из session object, но не подтверждают реальные email-flow, production RLS, grants или безопасность production Supabase.

## Безопасность изменений
Изменения ограничены SPA route guard и E2E-тестами. `main`, production, Supabase-конфигурация, база данных и deployment не изменялись.
