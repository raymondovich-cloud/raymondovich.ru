# 2026-11-12 — Устойчивость загрузки страницы авторизации

## Диагностика

Страница авторизации выводила исходную заглушку из `authorization.html`, пока клиентский модуль `auth.js` не заменит её формой входа. В цепочке авторизации Supabase JS загружался только с одного внешнего ESM-хоста (`esm.sh`). Ошибка загрузки этого импорта прерывала вычисление модуля до выполнения `renderAuth()`; обработчика ошибки на уровне точки входа не было. В результате пользователь видел бесконечное сообщение «Загрузка защищённой формы авторизации…».

Доступ к production-сайту из среды диагностики проверить не удалось, поэтому отказ CDN зафиксирован как подтверждённый риск в коде, но не как доказанная причина конкретного инцидента. Другие возможные причины (ошибка сети, блокировка CDN, ошибка любого статического импорта) теперь также получают пользовательское сообщение.

## Изменения

- Добавлен второй ESM-источник Supabase JS: при ошибке загрузки с `esm.sh` выполняется попытка загрузки с jsDelivr.
- Добавлена отдельная точка входа `auth-entry.js`, которая перехватывает ошибку импорта основного модуля авторизации.
- При фатальной ошибке вместо бесконечной заглушки показывается понятное сообщение и действие «Повторить загрузку».
- Production-файлы, Supabase-проект, база данных, секреты и настройки Auth не изменялись.

## Проверки и ограничения

- Проверено соответствие изменяемого script tag исходному файлу `index.html`.
- Статическая проверка синтаксиса и ручной браузерный тест должны быть выполнены в staging preview после публикации ветки.
- Не выполнялись вход, регистрация, восстановление пароля и проверка существующих сессий; для этого требуется ручной тест в браузере.
- Изменения находятся в отдельной ветке и не публикуются в `main`.
