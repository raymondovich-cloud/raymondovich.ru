# Изменения — 2026-11-10

## Единый UI-стандарт Owner Control Center

### Реализация

- Создан общий паттерн `workspace-ui.css`: toolbar, search, icon actions, filters, summary, progress, section headings, cards, accordion groups, empty states и заголовки подэкранов.
- Добавлены семантические `--ws-*` токены для тёмной и светлой тем; для небольшого текста светлой темы добавлен отдельный контрастный `--ws-accent-text`.
- Подключён общий паттерн в `index.html` перед `ideas.css`; `page-atmosphere.css` оставлен последним.
- Создан `workspace-ui.js` с API `workspaceToolbar`, `workspaceFilters`, `workspaceStatGrid`, `workspaceSectionTitle`, `workspaceScreenHead`, `workspacePageTitle` и `escapeHtml`.
- Реестр «Идеи» переведён на общий toolbar, filters, stats, section headings, cards и accordion classes. Добавлен единственный скрытый h1. Detail/form экраны используют общий заголовок. Прогресс переключается через data-атрибут, без `element.style.width`.
- Реестр «Проекты» переведён на общий toolbar, filters, summary, section headings, cards и groups. Сводка рассчитывается по фактическим неархивным проектам; в фокус попадают максимум два активных проекта с высоким/критическим приоритетом, остальные группируются по статусу.
- Формы и подэкраны проектов используют `.ws-screen-head`; обзор проекта с hero-блоком сохранён.
- Удалены устаревшие CSS-правила реестров из `ideas.css` и `projects.css`, перенесённые в общий паттерн.
- Создана спецификация `workspace-ui-standard.md`, версия 1.1, статус «На утверждении».

### Проверки

- Выполнен синтаксический разбор изменённых JS-модулей после исключения import/export деклараций — PASS.
- В `ideas.js`, `projects.js` и `workspace-ui.js` не обнаружены inline style, тег `<style>` или прямое обращение к `.style.`.
- В общем паттерне `workspace-ui.css` нет hex-цветов.
- В `ideas.js` удалено назначение ширины прогресс-бара через `.style.width`.
- Проверены наличие сохранённых data-атрибутов и соответствие helper API.
- Визуальная проверка в браузере и iPhone Safari не выполнялась. Контрольные ширины 320, 375, 390, 700, 768, 1100 и 1440 px не проверены через реальный браузер.

### Ограничения и риски

- В `project-modules/services.js` сохранено существующее позиционирование контекстного меню через `menu.style.left/top` — известный долг, оставленный без изменений по заданному ограничению.
- Изменения вносятся напрямую в `main`; production deployment требует отдельного подтверждения успешного GitHub Actions workflow. На момент записи статус публикации не подтверждён.
- Функциональные сценарии поиска, фильтрации, создания, открытия карточек, возврата и преобразования идеи в проект требуют ручной проверки после публикации.
