- Неактивные связи остаются доступными для управления в отдельной секции и не попадают в подключённые итоги.

- Архитектурная граница Projects обновлена до версии 1.2: fallback Services допустим только при явном `not_configured` Accounting; ошибка Accounting не подменяется ручной оценкой. Commit: `41ed7b309e91d228ea240851ef2b905dba78f8b1`.

## Этап 1 — платформенный bootstrap и адаптеры

**Дата:** 2026-11-10  
**Ветка:** `architecture/multi-platform-stage-0-2026-11-10`  
**Статус:** реализация в отдельной ветке; production не затронут.

### Изменения
- Добавлен публичный config-модуль с прежними Supabase URL и publishable key; клиент Supabase и auth redirect используют единый конфиг/bridge без изменения значений.
- Добавлены platform detection, ранний Telegram bootstrap, единый bridge и Telegram adapter.
- Telegram launch-параметры сохраняются в памяти, SDK загружается динамически только при Telegram detection, hash/query очищаются через replaceState до запуска navigation/router.
- Разрешённые startParam: projects, ideas, authorization, home; неизвестные значения не становятся маршрутами.
- Telegram BackButton синхронизируется с единым RaymondovichNavigation; внешние ссылки перехватываются только в Telegram/native.
- Добавлены safe-area и viewport tokens, Telegram theme mapping, safe-area для шапки, sidebar, footer и PIN.
- Не добавлялись service worker, PWA manifest, native adapter, зависимости, package.json, auth endpoint, Supabase DDL/RLS, secrets или изменения deploy.

### Ограничения и риски
- Telegram SDK is a runtime dependency loaded from the official `https://telegram.org/js/telegram-web-app.js?64` endpoint only after Telegram detection. The SDK is not vendored or integrity-pinned; Telegram can change the served script. If loading fails, the app continues with fallback behavior, but Telegram-native controls are unavailable.
- Telegram SDK query revision `?64` reflects the official documentation inspected on 2026-11-10; re-check before public Mini App launch.
- New same-origin modules are fetched by Web; no additional third-party request to Telegram is made in ordinary Web/PWA. Actual Network-panel verification remains outstanding.
- `supabase-js@2` remains unpinned by explicit scope; vendor strategy remains open.
- Existing alert/confirm calls and pre-existing `.style.left/top` in Services were not changed.
