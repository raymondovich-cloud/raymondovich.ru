# Изменения Architecture Rewrite Specification — draft 0.4

**Дата:** 05.11.2026  
**Ветка:** `architecture/spa-rewrite-2026-11-05`  
**Предыдущая редакция:** draft 0.3  
**Новая редакция:** draft 0.4

## Зафиксированные решения

По согласованию с владельцем дополнена глава 12 технического задания.

### Управление состоянием

- Введено разделение на URL State, Module State, Application State, Session State и Persistent State.
- Зафиксирован принцип единственного владельца каждого состояния.
- Адресуемое состояние закреплено за URL; локальное временное UI-состояние — за соответствующим компонентом или модулем.
- Запрещён прямой доступ модулей к внутреннему состоянию друг друга.
- Межмодульные сценарии координируются Application Layer через публичные контракты и use cases.
- Авторизация и сессия изолируются в Identity/Auth Module; клиентское состояние не считается механизмом обеспечения доступа.
- Серверное хранилище остаётся источником истины для постоянных бизнес-данных. Клиентский кэш не подменяет сервер.
- Уточнены требования к жизненному циклу состояния, отмене запросов, stale-response protection, cache invalidation и logout cleanup.
- Выбор State Management Library отложен до отдельного ADR после инвентаризации и определения стека.

### Обработка ошибок

- Разделены локальная обработка ожидаемых ошибок и глобальная обработка необработанных критических ошибок.
- Добавлены требования к ошибкам модулей и сквозных межмодульных сценариев.
- Зафиксированы требования к безопасным пользовательским сообщениям и диагностическим логам без секретов и чувствительных payload.
