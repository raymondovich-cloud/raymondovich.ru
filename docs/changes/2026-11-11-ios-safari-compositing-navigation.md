# Исправление визуального сбоя компоновки в iOS Safari

## Симптом
При переходах между вложенными экранами авторизованной части (Идеи, карточка проекта, модули проекта) часть интерфейса визуально отображалась как вложенная карточная поверхность. После сворачивания и повторного открытия Safari отображение нормализовалось. Это указывало на общий механизм отрисовки оболочки, а не на отдельные стили Идей.

## Причина на уровне реализации
Все переходы анимировали сам `.authenticated-app-content` — прокручиваемый контейнер приложения — через CSS `transform` в keyframes `rv3-tab-enter` и `rv3-push-enter`. В iOS Safari transform на overflow-scroll контейнере может создавать отдельный compositing layer; при последовательных переходах и возврате приложения WebKit может отображать этот слой некорректно до следующего пересчёта/перерисовки. Наблюдаемое восстановление после сворачивания Safari согласуется с таким сценарием.

## Изменение
- Удалены `transform` из keyframes переходов вкладок и вложенных экранов.
- Сохранён короткий переход через opacity, без трансформации прокручиваемого контейнера.
- Не менялись маршрутизация, DOM экранов, данные, Supabase и Production.

## Проверки и ограничения
- Статически проверено, что оба keyframe больше не меняют transform.
- Cloudflare Pages Preview должен пройти публикацию после commit.
- Реальное воспроизведение/проверка в iOS Safari остаётся обязательной: автоматический runtime-тест Safari в этой среде недоступен.
