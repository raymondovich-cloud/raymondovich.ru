# 2026-11-13 — Design System and public page

## Утверждение дизайн-системы
- Владелец утвердил текущую визуальную систему как Raymondovich Design System Baseline 1.0.
- Зафиксированы палитра, Light/Dark, типографика, сетка, поверхности, компоненты и motion.
- Самостоятельное изменение визуального языка запрещено без явного согласования владельца; технические исправления допустимы при сохранении утверждённого результата.
- Добавлен документ `docs/design-system/BASELINE-1.0.md` как источник правил изменения дизайн-системы.

## Выполнено
- Foundation 0.1: токены, темы Light/Dark, foundations и базовые компоненты.
- Motion primitives: появление, press feedback, раскрытие и fade-переходы.
- UI Components 0.3: формы, переключатели, статусы, меню, native dialog и адаптивные правила.
- Showcase 0.4: отдельная интерактивная витрина с разделами цветов, типографики, поверхностей, кнопок, форм, статусов, навигации, окон и анимаций.
- Для витрины созданы отдельные HTML, CSS и JS файлы; общие стили подключаются из `source/design-system`, дублирования дизайн-системы нет.
- Существующая preview-страница получила ссылку на полную витрину.

## Публичная главная страница
- Корневой `index.html` содержит только семантическую HTML-разметку и подключения файлов Design System; встроенные стили отсутствуют.
- В шапке слева размещён текстовый логотип `raymondovich`, справа — кнопка «Авторизация».
- Под шапкой, по центру доступной области, размещена единственная надпись «Сайт в разработке».
- Компоновка и адаптивные правила перенесены в `source/design-system/patterns/public-home.css` как паттерн дизайн-системы.
- Удалён прежний page-specific stylesheet из `source/presentation/public/public.css`.
- Кнопка авторизации визуально присутствует, но отключена до подключения реального сценария входа.

## Проверки и ограничения
- Проверены содержимое HTML/CSS и пути подключения файлов в репозитории.
- Визуальная проверка в реальном iOS Safari и других браузерах ещё не выполнена.
- WCAG-соответствие не заявляется.
- Продуктовые модули, Supabase и backend авторизации не затрагивались.
- Работа ведётся непосредственно в `main` по решению владельца проекта.

- Исправлено растягивание кнопки «Настройки»: контейнер содержимого профиля заменён с `<p>` на `<div>`, для него задана ширина 100%, кнопка переведена в блочную flex-модель с шириной 100%. Предыдущая реализация не давала ожидаемого результата из-за размещения кнопки внутри абзаца.

- Дополнительно устранена причина сжатия кнопки «Настройки»: родительская `.ds-workspace__view` использует `justify-items: start`, поэтому контейнер содержимого явно растягивается через `justify-self: stretch` и `box-sizing: border-box`.

## Hash-навигация рабочего пространства
- Рабочее пространство остаётся одним SPA с единой HTML-оболочкой `app.html`; отдельные HTML-страницы для разделов не создаются.
- Добавлены адресуемые hash-маршруты: `app.html#projects`, `#ideas`, `#team`, `#tools`, `#profile` и `#profile/settings`.
- При прямом открытии ссылки отображается соответствующий раздел; навигация обновляет hash без полной перезагрузки документа.
- Поддерживаются история браузера, кнопки «Назад/Вперёд» и восстановление активного раздела через `hashchange`.
- Заголовок вкладки синхронизируется с текущим разделом.
