# Исправление браузерных E2E-проверок

**Дата:** 06.11.2026  
**Ветка:** `architecture/spa-rewrite-2026-11-05`

## Основание

В CI run #388 установка зависимостей, unit-тесты, production build, build smoke checks и установка Chromium/WebKit завершились успешно. Браузерный набор показал 23 успешных теста, 7 ошибок и 2 пропуска.

Разбор отчёта выявил два общих источника ошибок:

1. E2E fixture записывал в Supabase session storage строку `e2e-access-token`, которая не является декодируемым JWT и не содержит стандартных claims. Для теста восстановления сессии заменён только синтетический токен на JWT-структуру с тестовыми claims и тестовой подписью. Реальные ключи, пользователи и Supabase данные не используются.
2. В заголовке страницы Cooperation текст до и после `<br>` не имел разделяющего пробела в текстовом содержимом DOM. Добавлен пробел перед переносом строки, визуальная структура заголовка сохранена.

Тест browser Back завершился на той же проверке заголовка Cooperation до фактического вызова `page.goBack()`. Поэтому run #388 не доказывает наличие дефекта browser history; после исправления заголовка тест должен пройти проверку навигации заново.

## Изменения

- `source/presentation/spa/views/public/Cooperation.vue`: добавлен пробел перед переносом строки в заголовке.
- `tests/e2e/public-and-routing.e2e.js`: синтетическая сессия теперь использует декодируемый JWT-подобный access token с актуальными `iat`/`exp`, идентификатором тестового пользователя и ролью из `app_metadata`.
- Проверки маршрутизации и доступа не ослаблялись; ожидания тестов не заменялись обходными проверками.

## Проверка и ограничения

- Повторный CI после этих изменений обязателен; до его завершения исправление не считается подтверждённым.
- Проверки используют синтетическую сессию и mock REST-ответы. Они не подтверждают реальную авторизацию, RLS или работу production Supabase.
- Production, `main`, DNS, hosting и deployment не изменялись.
