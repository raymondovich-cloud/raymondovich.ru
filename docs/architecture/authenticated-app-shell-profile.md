## 1. Назначение

Документ фиксирует поведение и границы авторизованной оболочки Raymondovich.ru. Публичная страница и формы входа/регистрации остаются отдельными интерфейсами. После успешной авторизации пользователь проходит приветственный экран и попадает в рабочую оболочку с нижней навигацией.

## 2. Состав оболочки

Нижние вкладки в фиксированном порядке:
1. Проекты;
2. Идеи;
3. Инструменты;
4. Профиль.

Панель использует safe-area браузера и Telegram WebApp, не перекрывает содержимое, скрывается при PIN-блокировке и полноэкранных формах. Верхняя публичная навигация и публичный футер скрываются внутри авторизованного интерфейса, но общий контрол возврата сохраняется. При переходе на публичный маршрут состояние авторизованной страницы очищается, и футер снова отображается.

Вкладка нижней навигации «Инструменты» пока сохраняет отдельную заглушку. Каталог инструментов размещён в Профиле отдельным маршрутом `#authorization/profile-tools` и доступен всем авторизованным ролям. Каталог разделён на четыре категории: «Инструменты разработки» (сервисы: инфраструктура и подключённые сервисы), «Инструменты продвижения» (маркетинг, сообщество в Telegram), «Инструменты интеграции» (ИИ, Telegram-бот) и «Инструменты анализа» (бухгалтерия, аналитика).

## 3. Навигация

Единственный источник истории — `window.RaymondovichNavigation`:
- вкладки и профильные разделы используют `navigateRoute`;
- вложенные экраны Projects/Ideas продолжают использовать `navigateScreen`;
- кнопка возврата использует общий контроллер;
- UI не создаёт независимую историю.

Маршруты описаны в `docs/architecture/navigation-history-architecture.md`.

## 3.1. Повторные переходы и загрузка данных

Авторизованная оболочка сохраняется между переходами по маршрутам `#authorization/*`: нижняя навигация и контейнер приложения не пересоздаются, активная вкладка обновляется через состояние существующих элементов.

Для реестров Ideas и Projects используется краткоживущий in-memory snapshot в пределах текущей вкладки браузера и конкретного пользователя:
- при повторном открытии сначала отображается ранее загруженный snapshot;
- актуализация выполняется в фоне;
- успешный ответ заменяет snapshot свежими данными;
- пустой snapshot считается валидным состоянием и не подменяется индикатором загрузки;
- ошибки фонового обновления не стирают уже отображённые данные;
- snapshot не разделяется между разными user ID и не сохраняется в persistent storage.

Переходы между маршрутами не запускают повторную CSS-анимацию содержимого: модульный DOM может обновляться при смене маршрута, но не должен дополнительно смещаться или проявляться через fade-in. Анимация оставлена только для первоначального приветственного экрана. Это исключает визуальный эффект повторного появления страницы при каждом переходе.

Это оптимизация отображения, а не источник полномочий: все запросы по-прежнему выполняются через существующие контракты и проверяются Supabase/RLS. После перезагрузки страницы первоначальная загрузка выполняется заново. Данные профиля и счётчики Control Center пока не включены в этот snapshot-механизм.

## 4. Профиль и источники данных

Роль читается только из `user.app_metadata.role`. Клиентские значения из `user_metadata` не определяют полномочия.

| Поле | Источник |
|---|---|
| Роль | `app_metadata.role` |
| Имя | `user_metadata.display_name`, затем `full_name`, затем локальная часть e-mail |
| Аватар | `user_metadata.avatar_url` или `picture`, только если URL валиден и использует HTTPS |
| E-mail | Supabase Auth user |
| Счётчик проектов | Application contract `getProjectsSummary()`, только в разрешённом контексте |
| Control Center | Только при `app_metadata.role === "admin"` |

Если источник отсутствует или недоступен, интерфейс показывает пустое/недоступное состояние, а не выдуманные данные.

Избранное подключается через единый application contract Favorites: он объединяет только доступные пользователю избранные проекты и идеи. Экран «Профиль → Избранное» является общим представлением того же источника, который питает подразделы «В фокусе» в Projects и Ideas. Отчёты пока не имеют подключённого источника данных и не показывают фиктивные отчёты или счётчики.

Каталог инструментов не подключён к механизму подписок и не предоставляет запуск инструментов. Подпись «Доступ по подписке» для обычных пользователей является информационным обозначением будущего правила, а не проверкой или выдачей entitlement. Владелец видит отметку «Доступ владельца». Управление модулями — только каркас со статусом «Скоро». Тарифы, цены, платежи и расчёт подписки не входят в текущую реализацию.

## 5. Права доступа

Текущая архитектурная граница Projects — admin-only. До отдельного утверждённого изменения серверных правил интерфейс не расширяет доступ партнёрам, ученикам или пользователям. Для ролей без разрешения показывается честное состояние «Нет доступа».

Owner Control Center отображается только для `app_metadata.role === "admin"`. Скрытие ссылки — только UI-ограничение; фактическая защита остаётся за существующей авторизацией и RLS. Схема БД, policies и серверные полномочия в этой задаче не меняются.

## 6. Изменение данных аккаунта

Presentation вызывает application use cases:
- `changeProfileEmail`;
- `changeProfilePassword`.

Application Layer использует Supabase Auth adapter в Infrastructure. Изменение e-mail требует прохождения штатного подтверждения адреса Supabase Auth. Пароль проверяется на минимальную длину и совпадение подтверждения.

PIN не реализуется повторно. Интерфейс вызывает существующий `RaymondovichPinGuard.changePin()`; блокировка и проверка PIN остаются в текущем механизме.

## 7. Design System

Визуальные правила находятся только в `source/design-system/`:
- `patterns/app-shell.css`;
- `patterns/profile.css`;
- семантические токены в `tokens/tokens.css`;
- значения светлой темы в `themes/themes.css`.

JavaScript управляет маршрутами, классами, data- и ARIA-атрибутами. Inline CSS, `element.style`, `setProperty` и новые зависимости не используются. Все поля ввода имеют размер шрифта не менее 16px. Анимации отключаются при `prefers-reduced-motion: reduce`.

## 8. Ограничения текущей версии

- Избранное реализуется отдельной персональной связью с проектом или идеей; soft delete сохраняет связь для восстановления, hard delete удаляет её каскадно.
- Отчёты не подключены.
- Каталог инструментов отображается в Профиле, но сами инструменты, подписочные права и подключения к проектам пока не реализованы.
- Управление модулями не подключено к подпискам или оплате.
- Счётчик проектов доступен только при наличии разрешения на чтение Projects.
- Визуальная и браузерная проверка должна быть выполнена в staging на iPhone Safari, Telegram Mini App и desktop перед публикацией.

## 9. Избранное как общий профильный раздел

- «Профиль → Избранное» — агрегированное представление проектов и идей, отмеченных текущим пользователем.
- Profile не владеет данными избранного и не дублирует их: он использует публичный application contract Favorites.
- Подразделы «В фокусе» в Projects и Ideas используют тот же источник и фильтруют объекты по своему типу.
- Персональность обеспечивается `user_id` и серверными RLS policies; клиентская фильтрация не является границей безопасности.
- Soft-deleted объекты не отображаются в активных представлениях. Связь избранного остаётся в БД и снова становится видимой после восстановления объекта.
- Текущие Projects и Ideas доступны только владельцу с `app_metadata.role = 'admin'`. Этот документ не расширяет доступ партнёрам или ученикам.
