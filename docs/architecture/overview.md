# Архитектура Raymondovich

## Принципы

1. Чистая архитектура.
2. DDD как способ разделения предметных областей.
3. Один файл — одна ответственность.
4. Доменные правила не зависят от интерфейса и инфраструктуры.
5. Design System отделён от бизнес-логики.
6. Новая функциональность добавляется в соответствующий слой, а не в универсальный файл.

## Слои

- `core` — фундаментальные типы и контракты.
- `domain` — предметные области и бизнес-правила.
- `application` — сценарии и orchestration.
- `presentation` — UI и пользовательские взаимодействия.
- `infrastructure` — внешние системы и реализации адаптеров.
- `memory` — состояние и данные приложения.
- `design` — визуальная система.

## Направление зависимостей

`presentation → application → domain`

`application → infrastructure / memory` через определённые контракты.

`domain` не импортирует `presentation`, `infrastructure` или `memory`.

`design` не содержит бизнес-логику.
