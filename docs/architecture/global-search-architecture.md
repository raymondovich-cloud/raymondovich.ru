# Global Search Architecture

> **Проект:** Raymondovich.ru  
> **Документ:** Архитектура глобального поиска авторизованного пространства  
> **Версия:** 1.2  
> **Статус:** Реализация первого среза  
> **Дата:** 2026-11-11

---

## 1. Назначение

Глобальный поиск предоставляет единый вход к доступным данным и разделам авторизованного пространства независимо от текущего экрана.

Поиск вызывается жестом Pull Down из любой точки экрана авторизованного пространства. Отдельная постоянная кнопка поиска не добавляется.

## 2. Область поиска первого среза

Первый срез включает:

- реестр проектов: название, описание и цель;
- реестр идей: название, описание, цель, концепция и дополнительные сведения;
- каталог инструментов: название, описание и категория;
- ресурсы: название, описание, тип и окружение;
- связи сервисов с проектами: назначение и заметки;
- связи ресурсов с проектами: роль и заметки;
- статические пункты доступных разделов приложения.

Разделы бухгалтерии, маркетинга и аналитики сейчас возвращают состояние not_configured и не содержат поисковых записей. Они не индексируются до появления реальных источников данных. Профильные настройки представлены как навигационные пункты, но персональные поля профиля не индексируются в первом срезе.

## 3. Слои

1. Presentation: authenticated-global-search.js управляет жестом, поисковой панелью, debounce и навигацией.
2. Application: source/application/search/global-search.js объединяет источники и формирует сгруппированные результаты.
3. Infrastructure: source/infrastructure/supabase/global-search-repository.js выполняет чтение через текущую Supabase-сессию.

Presentation не обращается к Supabase напрямую.

## 4. Безопасность и доступ

- Все запросы выполняются через текущую авторизованную Supabase-сессию.
- RLS остаётся единственным источником полномочий и фильтрации записей.
- Клиентский поиск не расширяет права роли и не заменяет серверную авторизацию.
- Поиск не запрашивает URL ресурсов, внешние идентификаторы и свободные заметки-подтверждения; отдельные поля секретов, токенов, PIN-кодов и учётных данных не входят в поисковый контракт. Секреты нельзя хранить в описаниях проектов, идей, инструментов или ресурсов.
- history.state получает только идентификаторы, необходимые существующим навигационным сценариям.
- Ошибка одного источника не скрывает результаты других; интерфейс показывает предупреждение о частичной доступности.

## 5. Жест Pull Down

- Жест может начинаться в любой точке экрана авторизованного пространства; ограничение по координате начала касания отсутствует.
- Жест активируется только при нулевой вертикальной прокрутке страницы. Если пользователь находится ниже начала страницы, вертикальное движение вниз сохраняет стандартное поведение прокрутки к началу и не перехватывается поиском.
- Горизонтальные жесты и взаимодействие с полями/кнопками не перехватываются.
- Порог открытия первого среза — 72 CSS px.
- Safari не предоставляет приложению точное значение нативного порога Pull to Refresh. Поэтому 72 px — фиксированное начальное значение реализации, а не измеренная половина нативного порога.
- Touch-события обрабатываются на уровне `document` в capture-фазе, а не только на корне приложения: это позволяет перехватить жест до того, как iOS Safari начнёт нативный Pull to Refresh.
- Нативное действие отменяется через non-passive `touchmove` сразу после подтверждения движения вниз (более 2 CSS px), а не после визуального порога подсказки. Визуальная подсказка по-прежнему появляется после 6 px, поиск открывается после 72 px.
- Проверка принадлежности начального касания авторизованному корню сохраняется; обработчики не перехватывают касания вне авторизованного пространства.
- Поддерживается системная клавиатурная команда Ctrl/Cmd+K и / для устройств с клавиатурой.

## 6. Навигация

- Идея открывается существующим экраном idea-detail.
- Проект, сервис или ресурс проекта открывается существующим экраном project-overview.
- Пункты разделов открываются через RaymondovichNavigation.
- Поиск доступен на приветственном экране и во всех экранах внутри авторизованной оболочки. Публичные страницы и экраны авторизации до входа не затрагиваются.

## 7. Ограничения и следующий этап

- Это поиск по существующим источникам, а не отдельный полнотекстовый индекс.
- Каждый источник возвращает не более 8 совпадений за запрос; для больших реестров потребуется серверная полнотекстовая индексация и пагинация. Текущая версия не гарантирует исчерпывающий поиск по объёмам свыше этого лимита.
- Результаты зависят от RLS и реальных прав текущей роли.
- Проверка рендеринга в iPhone Safari, desktop и Telegram Mini App должна быть выполнена отдельно. Статическая проверка кода не подтверждает корректность системного жеста на устройствах.
