# Целевая цветовая карта Raymondovich

> Версия: 1.0  
> Статус: Утверждена как целевая спецификация; значения проходят техническую проверку  
> Дата: 2026-11-11  
> Основание: `docs/architecture/color-token-inventory.md` и согласованные владельцем решения

## 1. Назначение

Документ переводит результаты инвентаризации в конкретную целевую карту цветов для светлой и тёмной тем Raymondovich.

Это утверждённая целевая спецификация для поэтапной нормализации. Текущий первый этап вводит семантический слой как совместимые alias к существующей палитре и намеренно сохраняет текущий визуальный результат. Переход к целевым цветовым значениям выполняется отдельными проверяемыми изменениями после проверки компонентов в обеих темах. Значения ниже утверждены как целевой контракт и проходят техническую проверку перед визуальным внедрением. Перед внедрением они должны пройти автоматический расчёт контрастности, проверку фактического композитинга прозрачных поверхностей и визуальную проверку всех авторизованных экранов в обеих темах.

Светлая и тёмная темы имеют равный приоритет. Ни одна не является запасной или автоматически полученной инверсией другой.

## 2. Утверждённые владельцем решения

1. Светлая тема использует более тёмный оранжевый для текста, иконок и значимых контуров; более яркий оранжевый допустим для декоративных заливок и градиентов.
2. PIN Lock сохраняет фирменный тёмный экран независимо от выбранной темы приложения.
3. При первом запуске Telegram Mini App порядок выбора темы: сохранённый явный выбор пользователя → тема Telegram → системная тема → тёмная тема как fallback.
4. Для обычного браузера сохраняется логика: сохранённый явный выбор пользователя → системная тема → тёмная тема как fallback.

Сохранённый выбор должен отличаться от автоматически определённого режима. Если пользователь выбрал «Системная» или «Автоматически», это состояние следует хранить отдельно от явного выбора Light/Dark, чтобы автоматическое значение не блокировало последующие изменения системной или Telegram-темы.

## 3. Уровень Foundation — базовые цветовые шкалы

Foundation задаёт палитры и примитивы. Компоненты не должны ссылаться на произвольные значения Foundation напрямую, если для их назначения существует Semantic token.

### 3.1. Нейтральная шкала

Предлагаемые опорные цвета, уже частично присутствующие в текущей реализации:

| Роль шкалы | Значение | Применение |
|---|---:|---|
| Neutral 950 | `#08090B` | Самая глубокая тёмная поверхность |
| Neutral 900 | `#101216` | Базовая тёмная поверхность |
| Neutral 850 | `#171A20` | Приподнятая тёмная поверхность |
| Neutral 100 | `#F3F4F6` | Базовая светлая поверхность |
| Neutral 0 | `#FFFFFF` | Чистая светлая поверхность |
| Neutral 150 | `#E9EBEF` | Приподнятая светлая поверхность |
| Neutral Dark Text | `#F4F5F7` | Основной светлый текст |
| Neutral Light Text | `#17191D` | Основной тёмный текст |

Шкалу нужно будет расширить промежуточными ступенями только по мере подтверждённой потребности компонентов. Не создавать десятки оттенков заранее.

### 3.2. Фирменная оранжевая шкала

| Роль | Значение | Ограничение |
|---|---:|---|
| Orange Bright | `#FF9A5B` | Декоративные блики и вторичные яркие акценты на тёмном фоне |
| Orange Dark Theme | `#FF762F` | Текстовые/графические акценты тёмной темы и фирменные действия |
| Orange Brand Mid | `#D65B1F` | Декоративный и градиентный цвет светлой темы; не использовать для обычного текста на белом без отдельной проверки |
| Orange Light Theme | `#B94C19` | Текст, иконки, значимые контуры и акцентные действия светлой темы |
| Orange Deep | `#A94416` | Допустимый более тёмный вариант для отдельных состояний, если проверка контраста требует усиления |

Не считать эти цвета взаимозаменяемыми. Их назначение определяется ролью и темой.

### 3.3. Статусные шкалы

Текущие значения Owner / Ideas / Workspace дают отправную точку:

| Статус | Dark theme | Light theme |
|---|---:|---:|
| Success | `#65C994` | `#218653` |
| Warning | `#E9A05F` | `#A6531D` |
| Danger | `#FF927C` | `#B33E32` |
| Info | Требуется отдельная общая шкала | Требуется отдельная общая шкала |

Info не унифицируется в этой редакции: в Profile уже есть отдельный синий цвет иконки, но это не доказывает, что он подходит как универсальный информационный статус. Значения будут выбраны после инвентаризации всех статусных применений.

## 4. Уровень Semantic — обязательная карта ролей

Ниже приведён целевой семантический контракт. Имена — предлагаемые новые канонические имена; текущие `--color-bg`, `--color-text`, `--ws-*` и другие переменные сохраняются как совместимые alias на этапе миграции.

| Semantic role | Dark theme | Light theme | Назначение |
|---|---:|---:|---|
| `--semantic-background` | `#08090B` | `#F3F4F6` | Главный фон приложения |
| `--semantic-surface` | `#101216` | `#FFFFFF` | Основная поверхность |
| `--semantic-surface-raised` | `#171A20` | `#E9EBEF` | Приподнятые элементы |
| `--semantic-text-primary` | `#F4F5F7` | `#17191D` | Основной текст |
| `--semantic-text-secondary` | `#A2A7B0` | `#555D68` | Вторичный текст |
| `--semantic-text-tertiary` | `#747B86` | `#626B77` | Вспомогательные подписи |
| `--semantic-border` | `rgba(255,255,255,.12)` | `rgba(20,24,30,.14)` | Контуры компонентов |
| `--semantic-divider` | `rgba(255,255,255,.08)` | `rgba(20,24,30,.08)` | Разделители |
| `--semantic-accent` | `#FF762F` | `#B94C19` | Акцентный текст, иконки, активные состояния |
| `--semantic-accent-strong` | `#FF9A5B` | `#A94416` | Усиленный акцент и состояния |
| `--semantic-accent-subtle` | `rgba(255,118,47,.14)` | `rgba(185,76,25,.10)` | Мягкая акцентная поверхность |
| `--semantic-accent-foreground` | `#100D0C` | `#FFFFFF` | Текст на основной оранжевой кнопке |
| `--semantic-success` | `#65C994` | `#218653` | Текст/иконка статуса успеха |
| `--semantic-warning` | `#E9A05F` | `#A6531D` | Текст/иконка предупреждения |
| `--semantic-danger` | `#FF927C` | `#B33E32` | Текст/иконка ошибки и опасного действия |
| `--semantic-focus-ring` | `#FF9A5B` | `#B94C19` | Видимый keyboard focus |
| `--semantic-selection` | `rgba(255,118,47,.30)` | `rgba(185,76,25,.20)` | Фон выделенного текста |

Значения для `border`, `divider`, `accent-subtle` и `selection` являются стартовыми. Их нельзя считать подтверждёнными по WCAG только на основании указанного alpha: итог зависит от поверхности под ними.

### 4.1. Primary action

- Dark: фон действия — `#FF762F`, foreground — `#100D0C`.
- Light: фон действия — `#B94C19`, foreground — `#FFFFFF`.
- Hover/pressed не должны менять контраст ниже требований для текста и значимых графических элементов.
- Градиентные кнопки проверяются по самой неблагоприятной точке градиента, а не по среднему цвету.

## 5. Уровень Component — отображение по компонентам

Компонентные токены описывают особенности компонента, но наследуют Semantic tokens, если отдельное значение не обосновано.

| Component family | Semantic mapping | Допустимая специфика |
|---|---|---|
| App shell | background, surface, border, text, accent | Полупрозрачная навигационная поверхность и её тень |
| Navigation | surface, text-secondary, accent, accent-subtle, focus-ring | Активный пункт, hover/pressed, safe-area |
| Profile | surface, divider, text, status | Семантически разные цвета иконок разделов допустимы |
| Owner Control Center | surface, surface-raised, text, border, accent, status | Фирменные многослойные градиенты, но не отдельная несогласованная палитра |
| Projects | surface, surface-raised, text, border, accent, status | Локальные карточки/группы сохраняют различия геометрии и плотности |
| Ideas | surface, text, accent, status, border | Собственный визуальный характер; оранжевый должен ссылаться на Semantic mapping темы |
| Authentication | background, surface, text, border, focus-ring, danger, accent | Нельзя оставлять legacy fallback-цвета в обход семантической карты |
| PIN Lock | отдельная фиксированная dark palette | Исключение из переключения темы; сохраняет текущую тёмную фирменную концепцию |
| Liquid Glass navigation | theme-specific material surface + border + shadow | Только навигационные и контекстные поверхности |
| Liquid Glass context menu | theme-specific material surface + border + shadow | Не использовать как материал больших областей с плотным содержимым |

Компонентные токены не должны дублировать семантические значения без причины. Например, `--color-app-shell-active` должен ссылаться на `--semantic-accent`, а не иметь самостоятельный hex в каждой теме.

## 6. Theme Mapping — два равноправных режима

### 6.1. Dark

- Базовая среда: глубокие нейтральные поверхности, без абсолютного чёрного повсеместно.
- Иерархия: `#08090B` → `#101216` → `#171A20`.
- Основной текст: `#F4F5F7`.
- Вторичный текст: `#A2A7B0`.
- Оранжевый: яркий, читаемый на тёмной среде.
- Тени и световые акценты должны оставаться сдержанными и не заменять границы там, где граница необходима.

### 6.2. Light

- Базовая среда: мягкий светло-серый фон, чистые белые поверхности и отдельный уровень приподнятой поверхности.
- Иерархия: `#F3F4F6` → `#FFFFFF` → `#E9EBEF`.
- Основной текст: `#17191D`.
- Вторичный текст: `#555D68`.
- Вспомогательный текст: `#626B77`.
- Оранжевый для текста и значимых элементов: `#B94C19`.
- Светлая тема должна иметь собственные тени, границы, прозрачность и материалы; не использовать просто инвертированные dark значения.

### 6.3. Liquid Glass

Liquid Glass остаётся ограниченным материалом для навигации и контекстных поверхностей. Не назначать один и тот же alpha/blur для обеих тем автоматически.

Для каждой темы отдельно подбираются:
- базовая подложка материала;
- степень прозрачности;
- blur;
- контраст границы;
- тень/elevation;
- читаемость поверх реального содержимого под материалом.

Точные числовые параметры материала не фиксируются до визуальной проверки на реальных экранах. Большие рабочие области и насыщенные данными панели остаются непрозрачными или достаточно плотными.

## 7. Предварительная проверка контрастности

Расчёт WCAG 2.x для указанных непрозрачных пар:

| Foreground | Background | Contrast | Result |
|---|---|---:|---|
| `#F4F5F7` | `#08090B` | 18.2:1 | AAA |
| `#A2A7B0` | `#08090B` | 8.24:1 | AAA |
| `#747B86` | `#08090B` | 4.67:1 | AA |
| `#17191D` | `#F3F4F6` | > 15:1 | AAA |
| `#555D68` | `#F3F4F6` | 6.05:1 | AA |
| `#626B77` | `#F3F4F6` | 4.91:1 | AA |
| `#FF762F` | `#08090B` | 7.48:1 | AAA |
| `#B94C19` | `#F3F4F6` | 4.64:1 | AA |
| `#100D0C` | `#FF762F` | 7.27:1 | AAA |
| `#FFFFFF` | `#B94C19` | 5.11:1 | AA |
| `#65C994` | `#08090B` | 9.80:1 | AAA |
| `#218653` | `#FFFFFF` | 4.57:1 | AA |
| `#E9A05F` | `#08090B` | 9.16:1 | AAA |
| `#A6531D` | `#FFFFFF` | 5.42:1 | AA |
| `#FF927C` | `#08090B` | 9.16:1 | AAA |
| `#B33E32` | `#FFFFFF` | 5.75:1 | AA |

Порог для обычного текста: 4.5:1. Для крупного текста: 3:1. Для значимых нетекстовых элементов и границ компонентов: 3:1 к соседнему цвету.

Важно:
- Таблица не является полным WCAG-аудитом интерфейса.
- Для светлой поверхности `#E9EBEF`, тёмной поверхности `#101216`, градиентов, прозрачности и blur нужно отдельно проверить фактические пары.
- Для полупрозрачных линий и focus-ring проверяется итоговый цвет после композиции с каждым применимым фоном.
- Для disabled-состояний действуют отдельные исключения WCAG, но они не должны становиться оправданием плохой читаемости.
- Цвет не должен быть единственным способом передачи статуса.

## 8. Связь с текущими токенами

Миграция должна выполняться без одномоментного переименования существующего API.

Предварительные alias-связи:

| Текущий токен | Целевой источник |
|---|---|
| `--color-bg` | `--semantic-background` |
| `--color-surface` | `--semantic-surface` |
| `--color-surface-raised` | `--semantic-surface-raised` |
| `--color-text` | `--semantic-text-primary` |
| `--color-muted` | `--semantic-text-secondary` |
| `--color-subtle` | `--semantic-text-tertiary` |
| `--color-line` | `--semantic-border` |
| `--color-accent` | `--semantic-accent` |
| `--color-accent-bright` | `--semantic-accent-strong` |
| `--color-ideas-accent` | `--semantic-accent` |
| `--color-app-shell-active` | `--semantic-accent` |
| `--color-app-shell-active-surface` | `--semantic-accent-subtle` |
| `--color-ideas-danger`, `--ws-danger` | `--semantic-danger` |
| `--ws-success` | `--semantic-success` |
| `--ws-warning` | `--semantic-warning` |

Alias нельзя вводить до проверки всех мест использования: часть текущих токенов имеет модульную семантику и может нуждаться в отдельном компонентном контракте.

## 9. Поведение выбора темы

### Браузер
1. Если пользователь явно сохранил Light или Dark — использовать этот выбор.
2. Если пользователь выбрал Auto/System или явного выбора нет — использовать `prefers-color-scheme`.
3. Если системная настройка недоступна — Dark fallback.
4. Переключение на Auto/System снова разрешает системе определять режим.

### Telegram Mini App
1. Явный сохранённый выбор пользователя Light/Dark имеет приоритет.
2. Если явного выбора нет или включён Auto — использовать Telegram `colorScheme` / theme parameters.
3. Если Telegram-параметры недоступны — использовать системную тему.
4. Если и она недоступна — Dark fallback.
5. При изменении Telegram theme parameters в активной сессии обновлять тему, только если пользователь не закрепил явный Light/Dark.

### Синхронизация браузерного UI
При изменении темы необходимо обновлять:
- `data-theme` на корневом элементе;
- `color-scheme`;
- meta `theme-color` для текущей темы;
- системные цвета браузерных form controls, если применимо.

Необходимость и точный способ устранения возможной вспышки базовой темы до инициализации JavaScript проверяются отдельно на реальных браузерах. Inline-стили и inline-скрипты не вводить в обход правил проекта.

## 10. План внедрения

1. Утвердить эту карту как целевую цветовую спецификацию.
2. Создать семантические alias в токенах, не меняя текущий визуальный результат.
3. Перевести глобальные foundation/component правила на семантические токены.
4. Привести Authentication к общей карте.
5. Сохранить PIN Lock как документированное исключение с собственной тёмной палитрой.
6. Постепенно перевести Owner, Ideas, Projects и Profile на общий semantic слой, сохраняя оправданные component tokens.
7. Реализовать приоритеты темы для браузера и Telegram Mini App, различая явный выбор и Auto.
8. Проверить все авторизованные экраны в Light и Dark, затем публичные страницы и Telegram Mini App.
9. Проверить контраст, состояния, Liquid Glass, reduced motion, safe areas и meta theme-color.

Каждый шаг — отдельный проверяемый вертикальный срез. Массовое удаление или переименование текущих токенов не допускается.

## 11. Что не входит в эту редакцию

- Изменение CSS/HTML/JavaScript.
- Удаление legacy-токенов.
- Изменение PIN Lock.
- Изменение Telegram theme integration.
- Настройка конкретных параметров blur, прозрачности и теней без визуальной проверки.
- Утверждение полного соответствия WCAG до проверки реальных экранов.
